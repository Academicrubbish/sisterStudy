## 1. 项目定位

为妹妹定制的安卓平板学习应用，替代商业学习机（3000-7000 元档）。

核心闭环：**拍错题（不会的题）/ 拍笔记（手写归档）→ AI 引导解题 / 知识点标注归档 → 出题检验（真题优先，AI 兜底）→ 练习自评 → 错题沉淀 → 间隔复习 → 薄弱点交叉分析 → 反哺出题**。

产品三原则：

1. **先提示后答案（苏格拉底式引导）**：AI 输出预生成的「引导阶梯」（诊断提问 → 由远及近的多级提问/提示），每级需用户主动触发；最终答案揭示前设「答案门槛」（先提交自己的答案，可跳过但记录）。全产品统一检验问题：**「这个功能是在替她思考，还是让她思考？」**——任何 AI 功能、prompt、UI 改动过此检验
2. **零娱乐元素**：无信息流、无社区、无游戏化诱导
3. **系统级管控兜底**：防沉迷靠平板未成年人模式，App 内不做（可被绕过，不投成本）

明确不做：同步教材课程、题库建设、语音交互、作文批改、多用户体系、社交分享、上架应用商店。

## 2. 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 前端框架 | uni-app（**建议 Vue 3 + Vite**） | 编译为 Android APK；Vue 2 已 EOL，新项目无历史包袱 |
| 后端 | uniCloud 阿里云（**新空间**） | 与 Toolbox 空间完全隔离 |
| 识题/识笔记模型 | 阿里云百炼 qwen3.6-flash | OpenAI 兼容接口，沿用 processOcr 调用方式 |
| 解题/讲解/标注/出题 | 智谱 GLM | prompt 分层：思路提示 / 完整解答 / 知识点标注 / 出题 |
| 联网搜索（真题） | 智谱 GLM `web_search_tool` | API 内置联网搜索，零额外接入；效果不佳再评估博查/Bing |
| 向量化 | 智谱 embedding-3 | 笔记/错题/题目三处消费：语义检索、去重、出题上下文召回 |
| Markdown 渲染 | markdown-it（客户端解析）+ mp-html | DCloud 插件 id=805，全端支持，配 latex / 代码高亮插件 |
| 公式保底 | renderLatex 云函数 → Base64 SVG | 平台无关，已验证 |
| Markdown 编辑 | textarea + 预览 | 仅用于修正 OCR 错字 |
| UI 库 | 待定（uni-ui / wot-design-uni / 自定义 tokens） | design 阶段定 |
| 打包 | HBuilderX 云打包，自用公共测试证书 | 不上架 |

## 3. 功能清单

### 一期 MVP（目标：妹妹能日常用）

**F1 拍照解题**（错题入口）
- 拍照或相册选图，支持多张
- 上传云存储 → processOcr 识别为 Markdown 题目文本
- 识别结果可编辑（textarea 修正错字）后提交
- generateSolution 写任务队列立即返回；processSolution 定时消费调 GLM
- **阶梯式引导输出（苏格拉底式）**：一次生成整棵引导树（诊断提问 + 3~5 级由远及近的提问/提示 + 分支提示 + 完整讲解 + 答案），客户端按状态机逐级揭示，零二次调用；选项为结构化选项，**错误选项映射错误根因（概念模糊/思路偏差/计算习惯）**；prompt 注入学生画像（年级 + 该知识点历史错误根因）
- **答案门槛**：揭示最终答案前先让妹妹提交自己的答案（软门槛，跳过会记录）；答案只允许出现在 answer 字段（prompt 硬约束，回归测试验证泄露率）
- 分期：M1 简化两段式（诊断+提示 → 完整解答）→ M2 完整阶梯 + 结构化选项 → M3 真·多轮自适应（轻量同步调用）
- 一次调用顺带产出：科目 / 知识点标注、错误根因初判（Toolbox processLearnNote 一次生成拆多段的手法）
- 结果页 Markdown 渲染（公式、代码高亮）
- 解题完成自动入错题本（origin=photo）

**F2 错题本**
- 列表：按科目 / 知识点 / 时间 / 来源（拍题 / 练习 / 复习）筛选
- 详情：题目原文（含原图）、讲解、掌握状态、来源
- 状态流转：未解决 → 已解决
- 拍题去重：新题与历史错题 embedding 比对，高度相似提示「这道题拍过」并关联历史

**F3 解题历史**
- 按 batch 查看历史解题记录（solution_log）

**F4 设备注册**
- 首次启动 registerDevice 生成 uid，本地缓存；无微信登录体系

**F5 笔记归档**（笔记入口，v0.2 新增）
- 拍手写笔记（多页多图）→ processOcr 识别 → textarea 修正 → 归档
- 归档时 AI 自动标注科目 / 知识点（可手动修正），按科目/时间组织
- 笔记详情 Markdown 渲染（含原图对照）
- 向量化入库（进入统一 embedding，供搜索 / 相关推荐 / 出题上下文）
- 如进度紧可挪二期，不阻塞闭环

### 二期（目标：像学习机）

**F6 出题工作流**（v0.2 升级，原「举一反三」）
- 触发入口：① 错题详情「来一道类似的」② 笔记详情「基于这篇笔记出题」③ 薄弱点页「针对薄弱点出题」
- 异步任务（task_type=exercise），流程：
  1. 组装上下文：知识点 + 向量召回的相关笔记片段 + 相关错题
  2. 调 GLM（开启 web_search_tool）联网搜索真题
  3. **AI 评估提取**：搜索结果能否构成条件完整、自洽的题目？
     - 能 → 采用，source_type=real，存来源链接
     - 不能 → AI 依据笔记上下文生成，source_type=ai，并**自验**（AI 解一遍自己出的题，解不出则重出）
  4. 新题与已有题 embedding 去重后入 practice_log，推送练习
- 所有生成的题标注来源（真题/AI）

**F7 练习作答**（v0.2 新增）
- 展示题目 → 妹妹纸上作答 → 点「看答案」→ 自评对错
- **做错自动入错题本**（origin=practice），随即进入复习队列
- 自评交互组件与 F8 复习复用同一套

**F8 间隔复习（SM-2 遗忘曲线）**
- 错题按遗忘曲线调度下次复习时间
- 复习模式：先只显示题目，笔算后点「看解答」自评（记不清 / 会了 / 很简单）→ 更新调度参数
- 首页显示今日待复习数

**F9 薄弱点分析**（v0.2 升级：笔记 × 错题交叉）
- 错误根因归类统计（概念模糊 / 思路偏差 / 计算习惯）
- **知识点交叉分析**：
  - 有笔记、常错 → 「学过但不会用」→ 反哺出题：优先应用型/变式题
  - 无笔记、常错 → 「可能漏学」→ 提示补笔记
  - 有笔记、少错 → 掌握良好
- 每周知识点分布报告

**F10 家长区**（App 内口令进入，口令哥哥保管）
- 数据：每日拍题量 / 笔记量、解题量、复习完成率、知识点分布、**真题占比**、近 7 天趋势
- 入口放设置深处，避免妹妹常逛

## 4. 从 Toolbox 迁移清单

### 直接搬运（代码基本不动）

| 内容 | 用途 |
|------|------|
| `processOcr` 云函数 | 拍错题 + 拍笔记共用识题链路（多图并行识别、合并 Markdown） |
| `processEmbedding` 云函数 | 向量任务消费（embedding-3），覆盖笔记和题目 |
| `renderLatex` 云函数 | 公式 SVG 兜底 |
| `cloudfunctions/common/` 公共模块 | API 封装等，按需裁剪 |
| `deployment.md` 文档结构 | 新项目部署文档模板 |

### 搬架构模式 + 改造

| Toolbox 资产 | 改造为 |
|------------|--------|
| generateLearnNote / processLearnNote（任务队列 + 定时触发器异步架构，一次调用产出多结果） | generateSolution / processSolution：解题 prompt、两段式输出、顺带知识点标注 |
| learn-zone 学习专区工作流（多来源采集 → 预览编辑 → 保存/AI 处理） | 拍笔记归档流（同构：OCR → 修正 → 归档） |
| dict / dictCategory 标签管理（简化版） | 科目/知识点标签体系（AI 自动标注为主 + 手动修正） |
| semanticSearch（混合检索） | 笔记搜索 / 错题去重 / 出题上下文召回 / 新题去重 |
| `ai_task_queue` / `ai_learn_logs` 表结构 | `task_queue`（加 task_type）/ `solution_log` / `practice_log` |
| `getRequest()` 延迟初始化 API 层风格 | 新 api/ 层沿用风格，去掉 `withAuth` |
| checkAiAlert / getAiStats 用量统计思路 | API 消费监控（防止无节制拍题打爆 token） |

### 不带过去

towxml、ColorUI、login（微信登录）、generateShareLink / getShareArticle（H5 分享）、changelog、daily_record 记录 CRUD、游客模式整套。

## 5. 新空间云函数与数据库

### 云函数

| 函数 | 来源 | 触发方式 |
|------|------|---------|
| processOcr | 搬运 | 客户端调用 |
| generateSolution | 改造 | 客户端调用（只写库立即返回） |
| processSolution | 改造 | **定时触发器**（消费 solution / exercise 两类任务） |
| processEmbedding | 搬运 | **定时触发器** |
| semanticSearch（可更名） | 改造 | 客户端 / 云函数内部 |
| renderLatex | 搬运 | 客户端调用 |
| registerDevice | 新写 | 客户端调用 |
| getReport | 新写 | 客户端调用（家长区聚合） |

### 数据库集合（草案，spec 阶段细化）

| 集合 | 说明 |
|------|------|
| device_user | uid、设备信息、注册时间、家长口令哈希 |
| note | 笔记 Markdown、原图路径、科目、知识点数组、uid、时间 |
| question | 题目 Markdown、原图、科目、知识点、错误根因、掌握状态、**origin（photo/practice/review）**、uid |
| practice_log | 练习题：题目、**source_type（real/ai）、source_url**、related_note_id、作答结果、自评 |
| solution_log | question_id / note_id、类型（提示 / 完整 / 变式题）、ai_result（引导树 JSON）、status、batch_id、**引导路径埋点（每级选项/提示次数/卡点/是否跳过答案门槛）** |
| task_queue | 复用 ai_task_queue 结构，**加 task_type（solution / exercise / embed）** |
| embedding | 向量表，结构照搬 Toolbox，覆盖 note / question / practice 实体 |
| review_schedule | question_id、SM-2 参数（ef / interval / reps）、下次复习时间 |

## 6. 需要开发者配合的事项

**现在（创建空间 / 项目时）**

1. uniCloud 控制台创建新空间（阿里云版），记下 spaceId
2. HBuilderX 新建 uni-app 项目（选 Vue 3），manifest 关联新空间
3. 确认智谱、阿里云百炼账户余额，**设置消费告警 / 限额**
4. 准备环境变量：智谱 API key（GLM + embedding-3 + web_search）、百炼 API key（qwen3.6-flash）
5. 拍板 Vue 2 / Vue 3（建议 Vue 3）

**开发期**

6. 平板开启开发者模式 + USB 调试，连电脑真机运行
7. App 名称和图标（云打包用，随手做一个即可）
8. 打通安装包分发流程（云打包 APK → 装到平板）

**上线时（交给妹妹前）**

9. 平板系统未成年人模式：应用白名单（只留学习 App + 必要工具）、每日时长、22:30-07:00 禁用
10. 设定家长区口令
11. 和妹妹约定使用规则（如：先自己想 10 分钟再拍题）
